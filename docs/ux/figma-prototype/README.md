# SDP-7 · Сборщик кликабельного прототипа

**Revision 04: 85 экранов, 686 переходов. Все переходы локального preview проверены кликами.** Последняя независимо подтверждённая облачная страница — revision 03. Установка revision 04, ссылка и нативный отчёт ещё ожидаются. MCP ограничен тарифом Starter. Плагин выполняется локально в Figma Desktop и не обращается к MCP или внешней сети.

## Запуск в Figma

1. Открой нужный дизайн-файл в **Figma Desktop** с правом редактирования.
2. Открой меню **Plugins → Development → Import plugin from manifest…**.
3. Выбери [manifest.json](manifest.json) из этой папки.
4. Запусти **Plugins → Development → SDP — Interactive Prototype Builder**.
5. Нажми **«Собрать прототип»** и дождись сообщения `Ready`.
6. Нажми **«Скачать отчёт проверки»**. Сохрани `sdp7-native-route-audit-v04.json`: в нём реальные ID экранов и результаты чтения всех реакций из Figma.
7. Закрой панель плагина. На новой странице будет выделен экран входа; нажми **Present ▶**.

Не импортируй `code.js` или SVG по отдельности. Для запуска рядом должны находиться `manifest.json`, `code.js` и `ui.html`. Если переносишь пакет на другой компьютер, копируй всю папку или распакуй ZIP целиком.

Плагин создаёт отдельную страницу `SDP-7 · Interactive revision 04` и сохраняет старые страницы. Повторное нажатие сборки в той же сессии не создаёт дубликат. Новый запуск плагина создаст ещё одну отдельную страницу. При ошибке сборки удаляется только страница этого запуска, после чего возвращается исходная страница.

Этот способ установки соответствует [инструкции Figma для локальных плагинов](https://help.figma.com/hc/en-us/articles/360042786733-Create-a-classic-plugin-for-development). Публикация плагина не выполнялась. Manifest не содержит чужого опубликованного ID; если конкретная версия Figma требует зарегистрированный ID, создай свой через **Development → New Plugin → Custom UI** и перенеси назначенный Figma `id` в этот manifest, не заменяя остальные поля.

## Честные границы прототипа

Это **кликабельные заранее заданные состояния**, а не работающее приложение. Поля заполняются образцами по нажатию; свободный ввод, реальная авторизация, настоящая загрузка файлов и серверное сохранение не реализованы. Состояние сохраняется внутри явно связанных saved-сценариев; переход к исходным сценариям через общую навигацию возвращает их начальные данные. Текущая вкладка и информационные элементы не обязаны иметь реакцию.

Сборка создаёт отдельные Figma frames, векторную графику, редактируемые TextNodes и области нажатия с `setReactionsAsync`. Это **не** полная библиотека переиспользуемых компонентов и Auto Layout: композиция фиксирована по координатам проверенных макетов. Нужны Manrope и IBM Plex Sans; при недоступности сборка сообщает об ошибке вместо незаметной подмены шрифта. Финальные переносы строк проверяются в Figma.

## Предпросмотр и проверки

Можно заранее открыть [локальный кликабельный просмотр](preview.html) в браузере. Он использует ту же карту переходов, что и плагин, но не доказывает, что плагин уже запущен в Figma.

Выполнено:

- проверка синтаксиса JavaScript;
- проверка всех целевых экранов, границ областей нажатия и достижимости 85 экранов;
- сценарные проверки новых административных операций, редактирования достижения и исходных маршрутов;
- тест сборки 686 реакций, защиты от повторного запуска и отката при ошибке на тестовом адаптере;
- реальные браузерные проверки preview в headless Chrome: ошибка и сохранение достижения, исправление и сохранение оценки, мобильная навигация, отсутствие ошибок JavaScript и горизонтального переполнения на 430 px;
- визуальная проверка отрисовок входа, ошибки формы достижения и ошибки оценки; базовые пять экранов проверены в revision 02.

**Ожидает независимого подтверждения:** установка revision 04 и чтение нативного отчёта; проверка новых сценариев и преподавателя/мобильной версии в Present; ревью другого участника. [Текущие результаты](../../../prototype/revision-04-review.md) отделены от исторических проверок revision 03.

## Файлы и воспроизводимость

`build_package.py` компилирует исходные макеты revision 02, дополнительные состояния и карту маршрутов в `prototype.json`, `code.js` и `preview.html`. `complete_scenarios.py` содержит новые сценарии revision 04. `runtime.js` — исходник сборщика и нативного аудита; `ui.html` — его панель. `render_revision.cjs` воспроизводит четыре новых SVG-экспорта. Плагин после сборки не требует Python, Node или установки npm-пакетов.

Разработчик может повторить проверки:

```text
python build_package.py
node --check code.js
node test_package.cjs
node test_preview.cjs <путь-к-node_modules-с-playwright> chrome
```

`test_package.cjs` проверяет контракт, а не эмулирует настоящий Figma API. Browser preview тестирует маршруты, а не доступность реального приложения. Не выдавать эти результаты за проверку серверных прав или интеграции с университетом.
